# Docs Site Design

**Date:** 2026-06-28
**Topic:** docs.irdoc.io — dedicated documentation site

---

## Overview

A dedicated documentation site at `docs.irdoc.io`, built as a single self-contained HTML file (`landing/docs.html`) following the same pattern as the existing landing page. Docs content is bundled into `landing/docs-content.json` at commit time via a Node.js script, making it compatible with a private GitHub repository. Deployed as a Cloudflare Pages project with a custom domain.

---

## Architecture

### Files

| File | Purpose |
|---|---|
| `landing/docs.html` | The docs site — all CSS, JS, and layout |
| `landing/docs-content.json` | All markdown content, keyed by doc path, generated by the build script |
| `landing/build-docs.js` | Node.js script: reads `docs/**/*.md`, outputs `docs-content.json` |

### Dependencies (CDN, no build step)

- **marked.js** — Markdown → HTML rendering
- **highlight.js** — syntax highlighting in code blocks
- **Fuse.js** — fuzzy full-text search, indexed at page load

### Deployment

Separate Cloudflare Pages project pointing to the `landing/` folder, with `docs.html` as the entry point and `docs.irdoc.io` as the custom domain. When the repo goes public, `docs-content.json` can be dropped in favour of runtime GitHub raw URL fetching with no other changes required.

### URL Routing

Hash-based. `docs.irdoc.io/#installation/wizard` maps to the doc at `docs/installation/wizard.md`. Browser back/forward work. Links are shareable.

### Private Repo Workflow

```
1. Edit a markdown file in docs/
2. Run: node landing/build-docs.js
3. Commit landing/docs-content.json
4. Cloudflare Pages auto-deploys docs.irdoc.io
```

When the repo goes public: switch to runtime GitHub raw URL fetching by setting `REPO_RAW` in `docs.html` and removing the JSON bundle step.

## Components

### Top Nav

- IRDoc logo (links back to `irdoc.io`)
- "Docs" wordmark
- Version badge (e.g. `v0.1-alpha`) — static string in the HTML
- Light/dark mode toggle — persisted to `localStorage`
- `⌘K` search trigger button

### Sidebar

- Sticky, independently scrollable
- Search input at top — filters nav in real-time, restores on clear
- Section groups (Installation, User Guide, Admin Guide, Developers, Changelog)
- Groups collapse/expand on click; active group auto-expands on load
- Active page item highlighted in orange accent
- Hamburger icon on mobile opens sidebar as an overlay drawer

### Content Area

- Markdown rendered by `marked.js`
- Syntax highlighting via `highlight.js` (dark/light theme switches with mode toggle)
- Copy button on code blocks (appears on hover)
- Callout boxes: lines starting with `> **Note:**`, `> **Warning:**`, `> **Tip:**` styled as coloured cards
- Heading anchors: H2/H3 get `id` attributes and a `#` link icon on hover
- Prev/Next page footer links based on manifest order

### "On This Page" Rail

- Desktop only (hidden below 1200px)
- Lists H2 and H3 headings of the current doc
- Scroll-spy: highlights the heading currently in view
- Fixed position, right side of content area

### Search — Sidebar Input

- Real-time filtering of the sidebar nav tree as user types
- Matching pages shown with term highlighted; non-matching pages hidden
- Clicking a result loads the doc and closes the filter

### Search — ⌘K Modal

- Triggered by `⌘K` / `Ctrl+K` or clicking the search bar
- Full-screen overlay with centred search input
- Results grouped by section: title + matching content excerpt
- Keyboard navigation: arrow keys move selection, `Enter` loads doc and closes modal
- `Escape` or backdrop click closes modal
- Animated in with scale + fade (matches landing page animation style)
- Fuse.js powers fuzzy matching across title and full content

## Data Flow

1. **Page load** — fetch `docs-content.json` (same origin, no auth)
2. **Index build** — Fuse.js indexes all docs by title + content (~60 files, <50ms)
3. **Initial doc** — load doc from URL hash, or default to `installation/wizard`
4. **Navigation** — clicking a sidebar item updates the hash, fetches content from the in-memory map, renders with `marked.js`
5. **Search** — Fuse.js queries the pre-built index, results rendered in sidebar or modal

## Visual Design

Inherits landing page design tokens (same CSS custom properties, same fonts). Adaptations for reading comfort:

- Default background: `--bg-2` (`#0d1117`) instead of `--bg` (`#080b12`)
- Content column max-width: `760px`
- Body font size: `16px`, line-height: `1.8`
- Light mode: inverts to near-white background, dark text, same accent orange
- Mode preference persisted to `localStorage`, defaults to dark

## Mobile Behaviour

- Sidebar hidden by default; hamburger button in nav opens it as a full-height overlay drawer
- "On this page" rail hidden
- Content area full-width with `20px` horizontal padding
- Search modal full-screen on mobile
- Breakpoint: `768px`

## Out of Scope

- Server-side rendering or build pipeline (no Vite, no framework)
- Authentication or gating of any docs pages
- Comments or feedback widgets
- Versioned docs (single `main` branch)
- Analytics (can be added later via Cloudflare Web Analytics snippet)
